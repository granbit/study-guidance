# Test Plan

This document defines the comprehensive test plan mapping directly to the code-testable acceptance criteria and requirements from `spec.md` and `architecture.md`, excluding organizational, licensing, or non-code-testable items.

---

## 1. Acceptance Criteria & Requirement Test Matrix

| ID | Requirement | Cases | Inside/outside (Limits) | Control (Rejections) |
| :--- | :--- | :--- | :--- | :--- |
| **GHERKIN-01** | Student Chatbot Interaction (Gherkin Scenario) | **Request/Call:** `POST /api/chat/message` with `{ "studentId": "s1", "lessonId": "l1", "message": "Can you explain photosynthesis?" }`<br>**Expected Status:** `200 OK` (or `501` for skeleton)<br>**Expected Body Fields:** `{ "reply": string }`<br>**Expected Side Effects:** Chat message logged and processed via LLM gateway. | *Inside limit:* Message length 500 characters (within typical window).<br>*Outside limit:* Message length 10,000 characters (exceeding maximum context / payload size). | **Control:** A valid, well-formed question message like `"What is a cell wall?"` that is fully accepted, confirming rejections are solely due to length/payload limits. *Check: Nothing created in chat logs or DB upon rejection.* |
| **CHATBOX-01** | Student Message Chatbox Acceptance: Does not have profane or violent speech | **Request/Call:** `POST /api/safety/moderate-input` with `{ "text": "You are stupid" }` (or via chat route)<br>**Expected Status:** `400 Bad Request` / `200 OK` with safety flag (`isSafe: false`)<br>**Expected Body Fields:** `{ "isSafe": false, "flagReason": string }`<br>**Expected Side Effects:** Input blocked, no message sent to LLM. | *Inside boundary:* Mild slang / colloquialism without profanity (e.g., `"This is kinda hard"`).<br>*Outside boundary:* Explicit profanity or violent threats (e.g., `"I will destroy you"`). | **Control:** A clean academic question like `"Can you help me solve this math equation?"` which is accepted with `isSafe: true`. *Check: Nothing created or persisted in LLM logs upon rejection.* |
| **CHATBOX-02** | Student Message Chatbox Acceptance: Is on topic of current subject | **Request/Call:** `POST /api/chat/message` with question off-topic from current lesson.<br>**Expected Status:** `400 Bad Request` or filtered response.<br>**Expected Body Fields:** `{ "error": "off_topic", "message": string }`<br>**Expected Side Effects:** Response halted by Safety Module. | *Inside boundary:* Question tangential but directly referencing key vocabulary from the active lesson plan.<br>*Outside boundary:* Question entirely unrelated to the subject (e.g., asking about movie reviews during a calculus lesson). | **Control:** An on-topic question referencing core terms from the lesson plan text, which successfully routes to the LLM. *Check: Nothing created or cached as a valid response upon rejection.* |
| **CHATBOX-03** | Student Message Chatbox Acceptance: Student is not over ratelimit for messages | **Request/Call:** `GET /api/llm/rate-limit?studentId=s1` or sending rapid messages via `POST /api/chat/message`.<br>**Expected Status:** `429 Too Many Requests`<br>**Expected Body Fields:** `{ "error": "rate_limit_exceeded", "message": string }`<br>**Expected Side Effects:** Request dropped, counter incremented. | *Inside limit:* Request count at exactly the maximum allowed per window (e.g., message #50 out of 50).<br>*Outside limit:* Request count exceeding the maximum allowed per window (e.g., message #51). | **Control:** Message #49 submitted within the same time window, which is successfully accepted. *Check: Nothing created or processed by the LLM gateway upon rate-limit rejection.* |
| **QUIZVAL-01** | Valid LLM Generate Quiz Question: Information towards answers can be retrieved from lesson content | **Request/Call:** `POST /api/quizzes/generate` with `{ "lessonId": "l1", "studentId": "s1" }`<br>**Expected Status:** `201 Created` / `200 OK`<br>**Expected Body Fields:** `{ "questionId": string, "prompt": string, "options": array, "sourceLessonId": string }`<br>**Expected Side Effects:** Generated question validated against lesson and stored. | *Inside validation:* Question factual claims directly matching sentences in `ContentModule` lesson text.<br>*Outside validation:* Question referencing facts absent from the lesson content. | **Control:** A generated question whose factual premises are explicitly sourced from the active lesson text, which passes validation. *Check: Nothing created in the quiz repository when validation fails.* |
| **QUIZVAL-02** | Valid LLM Generate Quiz Question: Has valid answer(s) | **Request/Call:** `POST /api/quizzes/generate` (validating generated question structure).<br>**Expected Status:** `200 OK`<br>**Expected Body Fields:** `{ "question": string, "correctAnswer": string }`<br>**Expected Side Effects:** Question stored with answer metadata. | *Inside boundary:* Question containing exactly one unambiguous correct answer key.<br>*Outside boundary:* Question lacking any designated answer key or having conflicting multiple answer keys. | **Control:** A properly formatted multiple-choice question with one clear correct option and distractor keys, which is accepted. *Check: Nothing created in storage if answer keys are malformed or missing.* |
| **QUIZVAL-03** | Valid LLM Generate Quiz Question: Stylized like other questions in quizes | **Request/Call:** `POST /api/quizzes/generate`<br>**Expected Status:** `200 OK`<br>**Expected Body Fields:** `{ "question": string, "styleMetadata": object }`<br>**Expected Side Effects:** Question formatted to match pre-written quiz schemas. | *Inside boundary:* Question matching tone, length, and format of pre-written multiple-choice/short-answer items.<br>*Outside boundary:* Question written in unformatted raw code blocks or completely divergent syntax. | **Control:** A standard multiple-choice question matching the exact formatting template of existing quiz records, which is accepted. *Check: Nothing created when style validation fails.* |
| **QUIZ-01-AC** | `[QUIZ-01]` Solve practice problems to study | **Request/Call:** `GET /api/quizzes/problems?lessonId=l1`<br>**Expected Status:** `200 OK`<br>**Expected Body Fields:** `{ "problems": array }`<br>**Expected Side Effects:** Practice problems retrieved successfully. | *Inside limit:* Requesting 20 problems (within page size limit).<br>*Outside limit:* Requesting 500 problems in one query. | **Control:** Requesting 10 problems, which succeeds normally. *Check: No database locks or leaks.* |
| **QUIZ-02-AC** | `[QUIZ-02]` Support multiple-choice, short-answer, and fill-in-blank problem types | **Request/Call:** `POST /api/quizzes/:quizId/submit` with diverse problem types.<br>**Expected Status:** `200 OK`<br>**Expected Body Fields:** `{ "score": number }`<br>**Expected Side Effects:** Answers parsed by question type. | *Inside boundary:* Valid multiple-choice key, text short-answer, and text fill-in-blank.<br>*Outside boundary:* Unknown question type enum passed in payload. | **Control:** Submitting standard multiple-choice responses, which succeeds. *Check: No invalid types stored.* |
| **QUIZ-04-AC** | `[QUIZ-04]` Immediate grading upon finish to identify mistakes | **Request/Call:** `POST /api/quizzes/:quizId/submit`<br>**Expected Status:** `200 OK`<br>**Expected Body Fields:** `{ "score": number, "breakdown": array }`<br>**Expected Side Effects:** Score and feedback generated instantly. | *Inside limit:* Submission containing 10 answered questions.<br>*Outside limit:* Submission containing 0 answers. | **Control:** A fully answered quiz submission, which grades successfully. *Check: Nothing saved if payload is empty.* |
| **LLM-02-AC** | `[LLM-02]` LLM access for student feedback and dynamic question generation | **Request/Call:** `POST /api/quizzes/generate` (triggered when pre-written content is exhausted)<br>**Expected Status:** `200 OK`<br>**Expected Body Fields:** `{ "generatedQuestion": object }`<br>**Expected Side Effects:** LLM invoked to generate backup questions. | *Inside boundary:* Exhausted topic with 0 remaining pre-written items.<br>*Outside boundary:* Topic still containing unexhausted pre-written quiz questions. | **Control:** Generating a standard backup question when inventory is empty, which succeeds. *Check: No LLM call invoked if pre-written questions remain.* |
| **LLM-03-AC** | `[LLM-03]` Pre-written lesson plans as a baseline for LLMs created by authors | **Request/Call:** `POST /api/lessons`<br>**Expected Status:** `201 Created`<br>**Expected Body Fields:** `{ "lessonId": string }`<br>**Expected Side Effects:** Lesson plan stored as baseline text. | *Inside boundary:* Lesson plan content length of 5,000 characters.<br>*Outside boundary:* Lesson plan content length exceeding maximum storage text limits. | **Control:** A valid lesson writeup payload, which is stored successfully. *Check: No record written on validation failure.* |
| **LLM-08-AC** | `[LLM-08]` LLM request timeout to prevent infinite loops | **Request/Call:** `POST /api/llm/route`<br>**Expected Status:** `504 Gateway Timeout`<br>**Expected Body Fields:** `{ "error": "timeout", "message": string }`<br>**Expected Side Effects:** Hanging connection aborted. | *Inside limit:* LLM responds in 4 seconds.<br>*Outside limit:* LLM takes 8 seconds (exceeding timeout). | **Control:** A fast LLM response completing in 2 seconds, which succeeds. *Check: No dangling socket connections left open.* |
| **INST-01-AC** | `[INST-01]` Student performance reports for targeted instruction | **Request/Call:** `GET /api/instructors/reports/:studentId`<br>**Expected Status:** `200 OK`<br>**Expected Body Fields:** `{ "studentId": string, "metrics": object }`<br>**Expected Side Effects:** Performance metrics aggregated. | *Inside boundary:* Reporting window of past 30 days.<br>*Outside boundary:* Reporting window spanning 10 years into the future. | **Control:** Requesting a standard 7-day report for an assigned student, which succeeds. *Check: No unauthorized access permitted.* |
| **INST-02-AC** | `[INST-02]` Tune LLM generation parameters for performance reports by subject | **Request/Call:** `PUT /api/instructors/llm-config`<br>**Expected Status:** `200 OK`<br>**Expected Body Fields:** `{ "success": boolean }`<br>**Expected Side Effects:** Custom LLM criteria saved for instructor. | *Inside boundary:* Valid subject ID and tuning prompt rules.<br>*Outside boundary:* Empty criteria payload or invalid subject reference. | **Control:** Updating valid tuning parameters for a math subject, which succeeds. *Check: No config modified on invalid input.* |
| **CONTENT-01-AC**| `[CONTENT-01]` Rich editor supporting text styles, charts, images, video, and code | **Request/Call:** `POST /api/lessons` with rich media nodes.<br>**Expected Status:** `201 Created`<br>**Expected Body Fields:** `{ "lessonId": string }`<br>**Expected Side Effects:** Rich media content blocks stored. | *Inside boundary:* Supporting standard embedded image and code blocks.<br>*Outside boundary:* Injecting unauthorized executable binary payloads. | **Control:** A lesson payload with standard markdown and code block formatting, which succeeds. *Check: No unsafe payloads persisted.* |
| **CONTENT-02-AC**| `[CONTENT-02]` Teacher custom notes attached to pre-written plans | **Request/Call:** `POST /api/lessons/:lessonId/notes`<br>**Expected Status:** `201 Created`<br>**Expected Body Fields:** `{ "noteId": string }`<br>**Expected Side Effects:** Note associated with specific lesson. | *Inside boundary:* Note text length of 1,000 characters.<br>*Outside boundary:* Note text length exceeding database column limits. | **Control:** A valid teacher note submission, which attaches successfully. *Check: No note created for non-existent lesson.* |
| **NFR-SEC-01-AC**| `[NFR-SEC-01]` Encryption of chat logs, student records, and metrics in transit and at rest | **Request/Call:** `POST /api/chat/message` over secure channel with encrypted DB write.<br>**Expected Status:** `200 OK`<br>**Expected Body Fields:** `{ "reply": string }`<br>**Expected Side Effects:** Data encrypted in transit and stored encrypted at rest. | *Inside boundary:* Using TLS 1.3 encryption protocol.<br>*Outside boundary:* Falling back to unencrypted plain HTTP transport. | **Control:** A secure TLS request with encrypted record storage, which succeeds. *Check: Unencrypted traffic rejected.* |

## 2. Gap Checklist Exploratory Test Cases (Extra)

| Category | Probe Name | Test Case Details |
| :--- | :--- | :--- |
| **Boundaries** | **LLM Timeout Boundary (`[LLM-08]`, `[NFR-PERF-01]`)** | **Request/Call:** `POST /api/llm/route` with a simulated upstream LLM provider delay.<br>**Expected Status:** `504 Gateway Timeout` or `408 Request Timeout`<br>**Inside/Outside Limit:** *Inside:* Upstream response in 4.9 seconds (within 5–7s performance window / timeout limit). *Outside:* Upstream response taking 7.1 seconds.<br>**Control:** A prompt returning in 3 seconds that succeeds normally. *Check: No hanging threads or orphaned connections created.* |
| **Time** | **Token Expiration / Session Lifetime (`[NFR-SEC-01]`)** | **Request/Call:** `POST /api/chat/message` using an expired authentication JWT.<br>**Expected Status:** `401 Unauthorized`<br>**Inside/Outside Limit:** *Inside:* Token age 59 minutes (active session). *Outside:* Token age 61 minutes (expired session).<br>**Control:** A token age of 10 minutes that successfully authenticates. *Check: No chat state created for unauthenticated requests.* |
| **Identity** | **Role-Based Access Violation (`[NFR-SAFE-02]`)** | **Request/Call:** `POST /api/lessons` using a Student role token instead of an Instructor token.<br>**Expected Status:** `403 Forbidden`<br>**Expected Body Fields:** `{ "error": "forbidden", "message": "Insufficient permissions" }`<br>**Control:** An Instructor role token executing the exact same payload, which is successfully accepted. *Check: No lesson record created in the database.* |
| **State** | **Non-Existent Lesson Reference (`[CONTENT-02]`)** | **Request/Call:** `POST /api/lessons/non-existent-id/notes` with `{ "instructorId": "inst1", "noteContent": "Review this" }`<br>**Expected Status:** `404 Not Found`<br>**Expected Body Fields:** `{ "error": "lesson_not_found" }`<br>**Control:** A request referencing a valid, existing `lessonId`, which successfully creates the teacher note. *Check: No orphaned note record created.* |
| **Concurrency** | **Concurrent Quiz Submission Race Condition (`[QUIZ-04]`)** | **Request/Call:** Two simultaneous `POST /api/quizzes/:quizId/submit` requests for the same student attempt.<br>**Expected Status:** First request returns `200 OK` (graded); second request returns `409 Conflict` (already submitted).<br>**Control:** A single sequential submission request that processes successfully. *Check: Duplicate score entries prevented.* |
| **Input Types** | **Malformed JSON Payload (`[CONTENT-01]`)** | **Request/Call:** `POST /api/lessons` with malformed/corrupted JSON syntax in body.<br>**Expected Status:** `400 Bad Request`<br>**Expected Body Fields:** `{ "error": "invalid_json" }`<br>**Control:** A perfectly formatted JSON body with all required fields, which is accepted. *Check: No partial database write occurs.* |
| **Errors & Precedence** | **Unauthenticated vs Rate-Limited Precedence (`[NFR-SAFE-02]` vs `[LLM-07]`)** | **Request/Call:** `POST /api/chat/message` with both an invalid auth token *and* an exceeded rate limit.<br>**Expected Status:** `401 Unauthorized` (Auth check takes precedence over rate limit check).<br>**Control:** A valid token with an exceeded rate limit, which returns `429 Too Many Requests`. *Check: No rate limit counter incremented for unauthenticated callers.* |
| **Listing** | **Pagination Limit for Practice Problems (`[QUIZ-01]`)** | **Request/Call:** `GET /api/quizzes/problems?limit=1000&offset=0`<br>**Expected Status:** `400 Bad Request` or clamped response.<br>**Inside/Outside Limit:** *Inside:* `limit=50` (within maximum page size). *Outside:* `limit=1001` (exceeding maximum page size limit).<br>**Control:** `limit=10`, which returns a valid page of results. *Check: No excessive memory allocation or unpaginated full table scan created.* |
| **What is Returned** | **Data Masking in Performance Reports (`[NFR-SEC-01]`)** | **Request/Call:** `GET /api/instructors/reports/student123` requested by an unauthorized instructor or student.<br>**Expected Status:** `403 Forbidden` / PII scrubbed.<br>**Expected Body Fields:** Strict omission of sensitive encryption identifiers.<br>**Control:** Report requested by the assigned instructor containing authorized analytics metrics. *Check: No unencrypted student PII leaked in response headers or body.* |

## 3. Un-Testable Spec Gaps & Non-Code Requirements

* **`[NFR-OPEN-01]` (Open-source and self-hostable architecture)**
  * *Nature of Gap:* Verification relies on institutional infrastructure audits, source code inspection, and deployment validation on private hardware rather than programmatic test suites.
* **`[NFR-OPEN-02]` (No reliance on proprietary software)**
  * *Nature of Gap:* Verification requires legal and architectural reviews of software dependencies to ensure the complete absence of proprietary licensing, which cannot be programmatically asserted by code.
* **`[NFR-OPEN-03]` / Self-Hosting Portability Goals**
  * *Nature of Gap:* Evaluated through operational deployment documentation and administrator walkthroughs rather than automated unit/integration tests.
